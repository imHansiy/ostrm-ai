# TiDB 限额期间临时使用 SQLite

AI 服务支持独立的 SQLite 数据库。恢复 AI 备份不会自动恢复 OpenList 本体的数据库；本体仍须能够提供经过其权限检查的视频信息和地址。不要把封面缓存、空 SQLite 文件当成完整备份。

## 切换前检查

1. 保留 TiDB 原库，备份当前 `.env`、安装代码、模型密钥文件、协议密钥及现有数据库快照。
2. 用 `PRAGMA integrity_check` 检查备份，核对视频、成功结果、人工标签、任务、订阅和协议索引数量。
3. 旧备份会缺少最近的结果。把已知在 TiDB 成功、但备份中没有结果的路径单独登记，不能伪造为已识别，也不能重新投递。
4. 停止 AI 服务，再恢复到新的数据目录。不要覆盖原数据目录，也不要同时启动两个识别服务。

## 配置

```dotenv
AI_DB_BACKEND=sqlite
AI_DATA_DIR=/absolute/path/to/separate-ai-data
```

数据目录中的 `aitags.sqlite3` 应当来自完整备份。保留原 `media-secret.key`，否则已有订阅链接会失效；若有 `model-secret.json`，也应当保留其内容及私有文件权限。压缩证据缓存可以复用，但必须匹配路径、文件指纹和提取参数；需要时可适当延长 `EVIDENCE_CACHE_TTL`，存储总量仍由原缓存上限约束。

内部设置 `restore_deferred_successes` 是“路径 → 远端成功记录校验值”的字典，保存于 `settings` 表。登记的路径会跳过扫描和入队，即使强制入队也不会执行；恢复时遗留的队列项也会跳过。这些记录等待以后从 TiDB 合并，不能填入编造的简介或标签。管理员更改此设置前应当保留恢复清单。

恢复任务应按路径去重，排除已经成功的视频和暂缓的挂载；旧任务的目录游标和新恢复批次应分别保存。先暂停调度，核对数据及模型配置，再小批量恢复。无法访问目录时可以先处理已知视频路径，暂缓重新遍历目录。

## OpenList 认证仍受数据库故障影响时

默认继续使用原来的管理员凭据。只有 OpenList 的现有 `/api/me` 在回环地址上**本身仍返回启用的管理员身份**时，灾难恢复选项 `OPENLIST_LOCAL_CACHED_ADMIN=true` 才允许复用该现有授权。它每次校验 OpenList 返回的实际角色，不会将访客提升为管理员，也不会允许远程主机使用此模式。

这不是恢复 OpenList 数据库的替代品。OpenList 重启或其缓存失效后，该模式可能停止工作；正常认证恢复后应关闭此选项。挂载、文件保护及管理权限仍由 OpenList 决定。

## 验证与迁回

- 健康接口必须报告 `database: sqlite`，并确认识别和协议后台线程运行。
- 对恢复前的成功结果、人工标签及屏蔽标签计算校验值，确认没有被改变。
- 验证一条真实视频完成压缩、模型推理、保存和外部协议查询；检查新文件确实写入本地库。
- 保存新结果和恢复批次清单，并定期通过 SQLite 备份 API 生成一致性快照；不要直接复制正在写入的数据库主文件而忽略 WAL。
- TiDB 恢复后，先暂停两侧写入并分别备份。按文件路径与指纹合并本地新增结果，保留 TiDB 已存在的成功结果、订阅身份和近期数据；核对人工修改。不要用旧 SQLite 快照全库覆盖 TiDB，也不要按可能冲突的任务编号盲目覆盖队列。
- 远端成功记录合并回来后，才移除相应 `restore_deferred_successes`。核对数量、结果校验值和队列状态后再切换服务。

迁回操作需要 TiDB 实际恢复读写后执行；本地恢复不会自动触发远端覆盖或自动回切。
